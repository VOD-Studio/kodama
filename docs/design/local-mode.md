# 浏览器本地模式

#13 的实现说明。本地模式让宠物住在浏览器里，不需要账号、后端或网络（PRD US-21、AC-09）。规则与服务端完全相同：每个动作都由同一个 WebAssembly 规则核心结算，再以一次原子提交写入本机存储。

入口是 `@violetjs/pet/local`，存储契约在 `@violetjs/pet/store`。

## 存储契约

与服务端 `pet-store` 相同的形状：`load(scope)` 读取版本与状态；`commit(scope, expected, requestId, changeset)` 一次写入状态与请求结果，返回已提交、重放、版本冲突或请求标识被换了参数四种之一，失败不出现部分提交。

| 实现 | 用途 | 验证 |
|---|---|---|
| `openIndexedDbStore()` | 浏览器本地存档：每次提交是覆盖两个对象仓库的一次读写事务 | 共享向量；状态已写入后结果写入失败，整体回滚；关闭后重新打开数据仍在 |
| `createMemoryStore()` | 测试与预览；明确不持久 | 共享向量 |

共享向量是 `tests/fixtures/store-contract.json`：Rust 的 SQLite、Postgres 实现与 SDK 的两个实现逐条运行同一份。新增实现时先跑通它。

## 存档格式

一个作用域（`local` 世界里的一位主人）存一份 JSON：

```json
{ "format": 1, "pet": { … }, "ledger": { "day": 20376, "ration": true, "exp": 30, "rewards": 2 },
  "appearance": { "species": 3, "genes": [ … ], "rarity": 0 } }
```

- `pet` 与服务端的宠物状态相同，由规则核心读写。
- `appearance` 是出生时确定的外形（物种、基因、稀有度）：宠物状态里没有这些字段，重新打开页面后靠它画出同一只宠物。
- `ledger` 是本地模式自己的当日账本，与宠物状态在同一次提交里写入，所以「领口粮」和「发奖励」不会只写一半。
- `format` 变化需要迁移（#5）。读到不认识的格式时报错，不猜。

## 时间

- 逻辑时间取本机时钟的分钟数。离开期间按同一套规则结算：离开再久，回来最多生病，不会直接死亡（见[参数](parameters.md)）。
- 本机时钟被调回过去时，宠物的时间停在最近一次结算，不报 `time_backwards`，也不会倒流。时钟拨快只是提前结算，代价由玩家自己承担，与刷取无关。
- 「本地自然日」按本机时区的午夜换日，用于口粮与奖励上限。
- `get()` 只结算投影用于展示，不写存储；只有动作会推进存档。

## 资源从哪里来

账号模式下，食物、药品与经验由服务按活动裁决（#12）。本地模式没有服务，资源规则由 SDK 固定：

| 来源 | 给什么 | 限制 |
|---|---|---|
| 出生 | 食物 5、药品 1 | — |
| `claimDaily()` 每日口粮 | 食物 3；手里没有药品时另给 1 份 | 每个本地自然日一次，重复领取返回 `already_claimed` |
| `reward(source, { exp, topic })` 活动奖励 | 经验（单次 0–100）与主题，**不给食物或药品** | 同一 `source` 只奖励一次；每个本地自然日至多 20 次、合计 100 经验，超出的经验不发，用完返回 `daily_limit` |
| 喂食、玩耍 | 经验 +1、+2（规则核心） | 受食物与精力限制 |

取值的理由：

- 一次喂食约抵一天消耗，每天 3 份口粮留出 2 份盈余，够每次进化消耗 3 份食物，也允许隔天来访。30 天每天领一次、喂一次的测试全程健康。
- 药品只在用完时补，生病仍需要照料，不会因为囤药而失去意义。
- 活动奖励不给食物，口粮是唯一的食物来源，养成的节奏不会被接入方的活动量改变；主题让「贤者」「辉耀」这些需要主题的分支在本地也能达成。
- 来源去重靠请求标识 `reward:<source>`，复用存储契约里的重放语义：同一篇文章读两次，第二次返回第一次的结果（`value.replayed` 为 true），不发奖励。

本地存档在用户自己的设备上，用户可以直接改 IndexedDB。上述限制是为了节奏，不是防作弊；这也是本地宠物没有出生证书、不能变成服务签发个体的原因。

## 并发与重放

- 多个标签页同时操作：版本冲突时重新读取并结算，至多重试 16 次，仍冲突返回 `busy`。测试用两个标签页并发喂食，食物恰好花完、不会花两次。
- 同一请求标识重放返回第一次的结果，并把 `value.replayed` 标为 true；换了参数返回 `request_conflict`。
- 已逝去的个体可以被新领养替换，新个体是新身份；当天的账本保留，换宠物不能重领口粮。

## 错误码

规则核心的错误码原样返回；存储与本地资源的错误：

| 错误码 | 含义 |
|---|---|
| `not_found` | 还没有宠物（与服务端同名） |
| `already_has_pet` | 已有在世的宠物（与服务端同名） |
| `request_conflict` | 请求标识已用于其他参数（与服务端同名） |
| `busy` | 并发冲突重试次数用尽 |
| `already_claimed` | 今天的口粮已领过 |
| `daily_limit` | 今天的活动奖励已用完 |

## 账号模式断网

PRD 要求账号模式断网时只保留动画与无收益的轻互动，不排队领奖、消费或进化。SDK 不提供任何离线队列：断网时用 `mountPet` 继续播放最近一次的投影，恢复后重新读取服务端的权威状态。本地存档不会自动上传或并入账号。
