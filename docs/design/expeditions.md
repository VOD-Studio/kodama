# 主题探险与收藏

#18 的实现说明，规则来自[扩展玩法评审](extensions.md)第 2 节。探险是第一个「消耗资源、换来产出」的新循环：主人选一个主题，宠物出门一段时间，带回少量经验和一件见闻。

## 规则

| 时长 | 出发消耗 | 带回的经验 |
|---|---|---|
| `short` 4 小时 | 食物 1 | 6 |
| `medium` 12 小时 | 食物 1 | 15 |
| `long` 24 小时 | 食物 2 | 30 |

- **出发** `{"depart": {"topic": "rust", "tier": "short"}}`：精力至少 30、没有生病、食物够、主题 1–32 字节；每个逻辑日（UTC）至多出发 2 次。
- **领取** `"return"`：到时间后结束探险，得到经验和一件见闻；没到时间返回 `still_away`。领取幂等：同一请求重放返回原结果，换个请求再领返回 `no_expedition`。
- **召回** `"recall"`：领取前随时可以召回，返还出发消耗的食物，没有产出。
- **探险期间**饥饿与病程照常结算，不暂停也不加速；主人仍然可以喂食、治疗与换装，宠物不会因为探险而死亡或受伤。玩耍、休息、进化与再次出发要等它回来（`on_expedition`）。

取值的理由：账号模式每天至多从活动得到 3 份食物，本地模式每天 3 份口粮，一次喂食约抵一天消耗，所以出发消耗必须小于一天的盈余；两次 4 小时的短途一天花掉 2 份，长途 24 小时花 2 份换 30 经验。经验量级与一天的活动上限（120）相比是补充而不是主要来源。这些数值没有试玩依据，评审已注明待试玩调整。

## 见闻

八种：明信片、彩色石子、羽毛、贝壳、星星碎片、旧地图、叶子标本、车票（名称在 `assets/catalog/souvenirs.json`）。每件见闻记录探险的主题，约十六分之一是闪亮的。

见闻由**宠物标识与探险编号**（出发那次请求的标识）经 HKDF 的独立通道 `expedition/v1` 确定：同一次探险在原生、Node 与浏览器里复算都得到同一件，且与出生（`pet/v1` 的出生派生）和进化的随机材料互不相关，增加探险不会改变任何出生结果（黄金出生向量照常通过）。

收藏册保留最近 24 件见闻，另按种类累计件数（`album`），所以存档大小有上限。

## 存储

宠物状态新增 `travels`，空时不写出，从没出过门的宠物存档与以前完全相同：

```json
{ "travels": { "trip": { "id": "x4", "topic": "go", "tier": "long", "departed_at": "…", "back_at": "…" },
               "day": "20376", "departures": 2,
               "recent": [ { "kind": "pebble", "topic": "rust", "shiny": false, "found_at": "…" } ],
               "album": [0, 1, 0, 0, 0, 0, 0, 0] } }
```

每天的出发次数记在宠物身上。评审要求按账号计算：一个账号同时只有一只主宠，两者相同；唯一的差别是宠物逝去后当天领养的新个体重新计数，而逝去本身需要多日失养，所以不值得为此单独记账。

## 客户端

- 动作经 `act`（规则核心）、`POST /v1/pets/me/actions`（账号模式）与 `@violetjs/kodama/local` 的 `act`（本地模式）执行，不需要新接口。
- `kodama act depart TOPIC short|medium|long`、`act return`、`act recall`；`live --account` 的状态行显示探险的主题与还有多久回来。

## 校验

规则测试 11 项：三档的消耗与回来时间；精力、食物、生病与主题的出发条件；每天 2 次、第二天重新计数；探险期间能喂食不能玩耍；探险期间的饥饿与在家相同；领取得到经验与见闻、重放不多给；召回返还食物且没有产出；见闻可复算、八种都会出现、闪亮约十六分之一；收藏册只留最近 24 件；没出过门的宠物存档不变；目录文件与代码一致。三端一致的转录包含出发、未到时间被拒、领取、再出发与召回。
