# 稀有 AI 伙伴：社区原型与进化美术基线

采用 ZipZipPipe 的成套 AI 娘形象作为终阶身份参照；DeepSeek 鲸娘另记录其原型作者上善无形。制作必须保留已有角色的发型、服饰和识别部件。

**2026-10-15 质量纠正：第一版由几何色块拼出的六位角色及自创小鲸已被用户否决，不属于可交付美术，已撤出预览。** DeepSeek 改为直接沿用用户指定网站上的 Deepy 小鲸鱼与鲸娘原样素材，不再重设计。其他六位重做，先制作 GPT 单角色造型样稿并与源鲸娘比较；单张高分辨率图不代表低分辨率精灵或动画已完成。SDK 接线通过测试，也不代表美术通过验收。

参照分为两层：**社区成年立绘确定角色身份、服装与识别部件；DeepSeek 的 Q 版比例、像素形态和终阶视觉，则直接以用户指定的 [dshtui 鲸娘](https://dshtui.com/pets/whale-girl-emoji/)为基线。** 后续适配延续这张已选像素鲸娘，不另画一个成年立绘的 Q 版来取代它。

这些形象在中文 AI 同人圈已有传播，存在不同作者、服装和画风的版本。本文锁定一套参照，方便后续保持一致，不将它称为全网唯一公认设定，也不将社区拟人形象称为官方吉祥物。

**七位从系列定位上全部属于稀有角色。终阶表示进化到最高阶段，不表示此前的幼体、少年不稀有。** 当前增加的是可选呈现接线与美术制作，不修改出生概率、出生证书、物种派生、养成数值或现有 v1 规则。

### 不同原型保持独立

Claude Code 的 Clawd 是另一条官方产品吉祥物路线。[官方更新记录](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)明确称其为 mascot，[员工发布帖](https://x.com/trq212/status/1972784970054893877)介绍其名称并使用螃蟹符号。这里采用的却是社区橙发 Claude 娘；没有证据表明「螃蟹进化为橙发少女」是社区既有设定，因此本套不接这条关系。以后若单独选择 Clawd 原型，应作为另一套设计记录。

Grok 的 Rudi 小熊猫与 Ani 拟人 Companion 也各自是独立产品角色，参见[产品发布帖](https://x.com/elonmusk/status/1944815884062912949)与[角色设计者发布帖](https://x.com/doganuraldesign/status/1944749965944738023)。不能声称 Rudi 会进化为 Ani。本套采用上表的 ZipZipPipe Grok 娘，不将 Rudi 的耳朵、环纹尾巴或 Ani 的其他版本细节拼接进去。

同理，Gemini 的官方星形标志、GPT 的官方品牌标志，与社区猫娘、龙娘是不同层次的来源。动物部件在这里来自所选社区版本，不能改写为厂商的官方动物设定。

- 有动物形象：幼体动物 → 少年 → Q 版拟人终阶。

## 从参考桌宠吸收的动作方法

参考入口为 [dshtui 宠物目录](https://dshtui.com/pets/)及[鲸娘表情桌宠](https://dshtui.com/pets/whale-girl-emoji/)。本轮核对其页面公开 JSON：该资源记录为 **69 × 66 像素、22 段循环、268 帧**，帧时长并不统一。这 22 段、268 帧已作为 DeepSeek 终阶源素材导入并保留原始时长；它们描述的是单一角色的原站资源，不代表七位角色或 26 项专属动作均已完成。

应吸收的是表演方式：

- **轮廓持续重画。** 肩、手、头、裙摆和尾巴发生明确姿态变化；不能只把一张静态人物整体上下移动。
- **动作有完整过程。** 前摇 → 主动作 → 过冲 → 回稳。抬手前先收肩，受惊前后有压缩与伸展，完成后留出回到基础姿态的过程。
- **各帧承担不同节奏。** 预备与收尾可以停留，主动作可以更快，不能强制所有帧等时播放。
- **附属层晚半拍。** 头部先转，长发、头鳍、龙翼、尾巴、裙摆随后跟进并逐渐停稳；各角色依据自己的部件分配动作。
- **像素与位置保持整数。** 以整数坐标落点、逐帧重绘和离散位移维持清楚边缘，不依靠插值模糊制造顺滑感。
- **表情参与身体动作。** 眼睛、眉、嘴、腮红与头身姿态协作；不能只在脸旁加一个符号就算新增表情。

正式像素画布、单动作帧数和总资源预算，要在终阶动作样片完成后确定。69 × 66 是参考资源的尺寸，不能直接当成本项目全部阶段的固定画布。原站鲸娘已按此原尺寸接入，Deepy 原导出帧按明确的 5:1 最近邻采样显示为 52 × 52；两者在对照工作台中使用相同 69 × 66 画布，保留透明外边距。当前 100ms 呈现时钟采样原时长，因此不宣称完整重现原站 20fps；原始帧与时长保留在可复现资源中。

### 网页与终端使用同一像素数据

Canvas 只是网页绘制方式，不是独立美术。两端共享核心输出的 `Pixels.rows`、`palette`、动作和呈现时刻。终端每个 `▀` / `▄` / `█` 格子表达上下两个像素，因此本次对照为网页 69 × 66、终端 69 列 × 33 行。

`Frame.fg_rgb` / `bg_rgb` 保留原始 RGB，真彩色输出使用 24 位颜色；原 `colors` / `bg` 仅保留为 256 色降级兼容。半块字形按原始 RGB 和透明状态决定，不能因两种相近颜色量化到同一索引就合并成一色。Deepy 的半透明阴影在核心以固定离散图案统一处理，两端获得相同的透明采样和原 RGB，不只在某一端丢弃透明度。

已验证实际终端 ANSI 字节解码后与网页 sprite 的 RGB / 透明像素逐格相同，包括两种既有 DeepSeek 形态、同阶段与同时刻、相近颜色碰撞、原阴影。浏览器对照区显示真实 `frame.rows` 文本；它使用仅含四种矩形字形的预览字体消除浏览器行间缝隙，未把终端输出替换成图片。实际终端的物理比例仍取决于字体格尺寸；256 色、16 色、NO_COLOR 或空间不足的降级不能被称为原色一致。

本机入口为 `make companions-preview` 与 `make companions-terminal`。当前只有 DeepSeek 的既有源素材可用；其余六位虽保留角色标识，`sprite` / `frame` 请求会明确返回美术尚未就绪的输入错误，不展示被否决的旧稿。这些技术验证不代表其余六位美术、独立少年形态或完整 26 项专属动画已经通过验收。

## 六种表情基线

表情与动作分别管理。一个思考动作可以使用好奇或专注表情；同一种喜悦表情也可以出现在进食、完成和赞许中，不能用六张表情图冒充六段动画。

| 表情 | 脸部与身体要点 |
|---|---|
| 平静好奇 | 眼睛自然睁开，眉势放松，视线有目标；允许轻偏头。 |
| 专注思考 | 视线集中、眉眼收紧或下移，嘴部收住；配合停顿与小幅手势。 |
| 害羞脸红 | 目光回避、腮红和嘴形改变，肩或手向内收；不能只有颜色变化。 |
| 喜悦闭眼 | 清楚的弯眼或闭眼笑、上扬嘴形，头身随笑容轻抬；与睡眠闭眼区分。 |
| 受惊汗滴 | 眼睛放大、眉嘴打开、身体后缩，汗滴作为辅助；不能让汗滴代替整套反应。 |
| 俏皮得意 | 视线、眉势、嘴角和重心共同表达得意；可用单侧眯眼，但保留角色的眼部特征。 |

每种表情需要静态表情参考及进入、保持、退出的动作说明。六种表情是后续图稿要求，当前并未完成七位的表情图或动画。

## 26 项动作规范

## 宿主事件、生命周期与降级

工作、并行、施工、报错、完成、等待确认等来自宿主活动。宿主只能驱动呈现状态，不能通过播放动画修改食物、经验、性格、健康、进化资格或死亡结果。生病、生命终结与进化仍依据规则核心和宿主已有的可信投影判断；动画不能成为数值结算入口。

临时动作完成、被打断或超时后，应回到**当时最新的基础态**，不能恢复触发动作之前缓存的旧状态。例如工作庆祝结束时宿主已切换到等待确认，应显示等待确认；进入生命终结后不能因为上一个戳碰动画结束又恢复走动。事件重复、缺失或乱序时也要有确定的退出与回退行为。

网页正式接入延续现有的后台暂停、暂停/恢复、卸载清理和无障碍名称行为。开启减少动画时使用清楚的静态关键姿态，关闭循环位移、闪烁和持续抖动；进化可以直接显示阶段前后的静态结果。为操作提供文字名称，不让情绪只能依靠颜色和细小装饰理解。

终端需要单独验证可读性：支持半格像素的终端尽可能保留脸、主发色、耳/鳍/角翼尾与原服装轮廓；小区域采用简化姿态。ASCII 或低色终端使用更简的身份符号与状态文字，不承诺还原细腻表情。精细画风若采用独立高分辨率资产，不能直接声称现有 56 × 36 像素模板或三行字符画已经支持这些角色。

## 稀有美术质量验收

验收依据是角色辨识度与完整表演，不以光环数量、金色描边或增加发光效果代替稀有质量。

| 检查 | 通过条件 |
|---|---|
| 原型一致 | 与选定原帖逐项比对发型、服饰、左右结构和识别部件；不混入另一作者或官方吉祥物路线的部件。 |
| 七位可区分 | 去掉文字标签后仍能靠剪影、脸、发型与附属部件区分，不只依赖近似色差。 |
| 三阶段成立 | 幼体、少年、终阶身体比例与轮廓有实质变化；并排看存在连续成长关系。 |
| 六表情成立 | 六种表情的眉眼、嘴形和身体姿态明确不同；缩小到实际显示尺寸仍能辨认。 |
| 动作成立 | 逐段播放后能辨认动作意图，包含前摇、主动作、过冲、回稳；待机与工作不靠同一张立绘抖动区分。 |
| 部件连续 | 长发、裙摆、耳鳍、翼尾与身体衔接稳定，延迟自然；轮廓不跳切、锚点不漂移。 |
| 像素稳定 | 整数落点、透明边缘清楚；没有缩放插值糊边、逐帧尺寸漂移或裁切。 |
| 状态正确 | 临时动作退出到最新基础态；减少动画、后台暂停、终端降级有可读结果。 |
| 来源可追溯 | 实际采用的每张参照与每份交付资产记录作者、来源、改编关系和使用条件，不把整理站当作代授权方。 |
| 独立视觉复核 | 制作者之外的评审者查看实际尺寸静帧、循环播放与阶段对照，记录问题和复查结果。 |

当前这些是验收条件，尚未形成七位完整图稿、动画或独立验收通过记录。

## 实施顺序与交付边界

1. **锁定参照。** 逐角色建立原帖与立绘对照，标清当前套的服装、部件与左右结构；若用户选择另一现成版本，先修改参照记录。
2. **先适配终阶。** DeepSeek 延续用户已选的 dshtui 像素鲸娘；其余六位按固定社区形象制作 Q 版适配和六表情。先审核辨识度，再制作动作。
3. **补前两阶。** 按动物/非动物规则设计幼体与少年，与终阶并排审核。前两阶是项目新增适配，不冒称原作者设定。
4. **做动作样片。** 先用待机、移动、思考、完成、戳碰与进化验证表演方法，再覆盖 26 项清单，逐帧记录非等时播放与退出契约。
5. **接入呈现。** 确定资产格式、画布、锚点、时钟和宿主事件映射，验证网页与终端的生命周期、无障碍及降级表现。
6. **另行接出生与养成。** 只有确定要加入真实出生池时才调整规则与证书。现有 v1 出生派生固定为 8 个物种；改变出生池或按稀有角色分配物种时，需要新出生规则版本、保留 v1 派生和旧证书核验，不能重写黄金出生向量让测试通过，详见[版本策略](versioning.md)。

**当前实际状态：** 已保留社区原型与动作标准，完成可选 companion 的 Rust/SDK 接线、本地工作台和实际终端预览。原站鲸娘与 Deepy 源帧已导入并完成同帧 RGB 回环验证。第一版六位程序拼图被否决并退出编译与公开呈现路径。GPT 的两张新造型研究仅保留在本地，未纳入仓库或运行素材；它们仍不是合格运行精灵，其余角色等待同一质量标准成立后制作。

**仍待交付：** 其余六位通过验收的 Q 版终阶、幼体与少年图稿、专属表情与动作、完整运行验证和独立视觉验收。现有测试只证明接线与渲染契约；概念图只证明造型方向，不能作为可运行帧、三阶段或动作已完成的证据。
