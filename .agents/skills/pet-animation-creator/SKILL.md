# 通用宠物与角色动作创作

从角色想法或已有参考素材出发，按用户指定的行为生成动作；可以只做一个动作，也可以制作一套动作库。不绑定特定角色、物种、动作清单、视频服务、素材管线或播放器。

## 执行原则

- 用户要求优先，其次是已有角色与素材约定，再次是目标运行时契约；未指定的创作细节才由你设计。约束相互冲突时指出冲突并提供可行选项，不静默改掉用户的形象或动作。
- 形象在同一个角色内保持一致，不在不同角色之间套用固定模板。用户说“你自己设计”时，根据本次主题提出并采用合适的新设计，不重复指定同一只默认宠物。
- 动作清单来自用户或本次角色设计，不要求凑齐待机、转向、拖拽等预设集合；生成数量等于实际需求。一个交互入口可以有多个不同表演，也可以不启用该入口。
- 允许不同动作有不同长度、姿态与循环方式。角色可以是动物、人形、机械、植物、幽灵或抽象生命体；不默认都有双脚、手臂、尾巴或固定骨架。
- 只执行用户要求的交付层级。不因用户要提示词就调用生成服务，不因用户要单个动作就安装播放器或重做整套宠物。
- 先检查真实可用的工具与生成服务。图片分析不是图片生成；未调用服务不得声称已经生成；没有凭据或不支持所需能力时，交付可直接执行的提示词、明确素材缺口，不制造占位成品。
- 保留现有素材和用户修改。新动作使用独立名称；同名迭代保存新版本，不覆盖已验收版本，不顺手替换角色或既有动作。

## 1. 判断本次任务

|任务|执行范围|完成条件|
|---|---|---|
|从零设计角色与动作|角色身份、参考图、用户需要的动作、指定格式输出|角色与所需动作均符合本次要求|
|为已有角色增加动作|复用身份、参考图、画布与锚点，只增加指定行为|新动作与旧动作可衔接，旧素材不变|
|只生成提示词|输出角色约束、动作规格和每段完整提示词|每段可独立使用，无需用户拼接“同上”|
|处理已有媒体|读取实际元数据，抠像、对齐或转码|导出满足目标规格，不改变未要求修改的动作|
|接入运行时|读取真实配置与素材规范，绑定已验收动作|配置有效、素材可加载、目标交互实际运行|

先从用户描述、已有文件和目标项目取信息。只问会实质影响结果且无法从上下文确定的问题；相关问题一次问清。用户已经明确的角色、动作、秒数、格式不能重复询问。

至少确定：本次交付层级、角色来源、动作意图、循环/结束方式、是否需要透明、目标用途。提示词阶段不必为了最终尚未确定的编码器阻塞创作。

## 2. 固定角色身份，而不是固定角色种类

新角色建立简短身份卡；已有角色读取并沿用其设定与参考图，不重新设计：

- 名称与稳定标识、物种/形态、性格及表演气质。
- 身体比例、轮廓、五官、肢体结构、材质和画风；像素、手绘、剪纸、3D 等均可。
- 主辅色、服饰、标记、装饰物及不可漂移的辨识特征。
- 默认朝向与可用视角；非对称装饰的位置，以及是否允许镜像。
- 基准姿态和锚点：站立角色可用脚底，漂浮角色可用躯干中心，爬行角色可用接触面。锚点是坐标参照，不是禁止角色运动。
- 本次允许变化的部分，例如表情、衣物运动、身体伸缩或明确要求的变形。不能用“禁止任何变形”否定史莱姆变形等动作本身。

母图优先使用一张干净、单角色、完整轮廓的基准姿态图。侧面、背面或道具参考可以单独补充，不把多视角拼图直接当成单角色视频第一帧。

已有角色保留原色；绿色角色不为方便抠像而改色。选取不与角色和道具冲突的纯色背景，或使用真正透明素材/分割路线。新角色也不默认禁止绿色。

以下是内部提示词模板，执行时必须展开成具体描述，不能原样交付变量：

```text
生成一张用于角色动作制作的参考图。
角色身份：{完整的形态、比例、五官、配色、服饰和辨识特征}。
画风与材质：{本次指定风格}。
姿态与视角：{本次基准姿态、朝向、镜头角度}。
构图：{画幅、主体大小、锚点、安全留白}，完整显示所有需要保留的部位。
背景：{适合当前角色的透明或纯色分离方案}。
保持：{必须固定的身份特征}。
避免：{本次不希望出现的额外角色、部件、文字或背景元素}。
```

## 3. 为任意动作建立动作卡

动作可以是理毛、踩奶、甩水、打喷嚏、蓄力、施法、充电、解体重组、变形、跳舞、吃东西或用户提出的其他行为。这些只是例子，不是允许动作的枚举。

每个动作先明确以下内容；简单需求可用短表，不强制创建新格式的配置文件：

|字段|需要确定的内容|
|---|---|
|动作标识与名称|稳定英文文件名与可读名称，沿用目标项目命名约定|
|行为与情绪|具体做什么、力度、节奏、情绪变化，避免只写“可爱一点”|
|身体与道具|哪些部位参与、道具从哪里来、结束时是否保留|
|播放语义|循环、一次性、姿态过渡，或进入/持续/退出组合|
|起始与结束状态|姿态、朝向、锚点、道具、表情；不默认站立或首尾相同|
|时长与节奏|用户要求的秒数或帧数；未指定时按行为和生成能力选择并说明|
|空间运动|原地表演、真实位移、跳跃、绕轴旋转或自由运动|
|镜像约束|是否允许水平镜像，是否必须另画左右版本|
|目标输出|按任务选择透明视频、PNG 序列、spritesheet、静态关键姿势或其他真实支持的格式|

### 首尾状态契约

- **循环**：首尾姿态、位置、朝向与运动相位连续。不要在每次循环结束硬插站立停顿；循环缝既检查位置也检查速度、呼吸和道具相位。
- **一次性表演**：定义明确的开始和结束。可回到初态，也可以结束在坐下、趴下、惊讶等新状态；只在需要衔接的情况下安排复位。
- **姿态过渡**：从 A 到 B，例如站立到蜷卧、收翼到展翼。结尾必须是 B，不能为了“闭环”又回 A。
- **持续状态**：需要运行时中途进入、维持和退出时，设计 enter → hold/loop → exit，三段边界分别匹配。一个“充电”需求可以对应多段素材，但不因此附加无关动作。
- **转向**：先确认运行时是否在片尾自动切换镜像。没有该机制时只制作用户指定的朝向变化，不擅自翻转下一段。

### 空间与时间契约

- 对桌宠原地动画，镜头默认固定，角色整体平移由运行时负责；用户明确要求画面内位移或运镜时按需求制作，不一律禁止。
- 跳跃允许离开地面，游泳/飞行不强制落地，漂浮角色不套脚底线。规范化只统一坐标系，不能抹掉动作轨迹。
- 同一角色与用途共享舞台比例和基准尺度，给全片极限姿态、尾翼、道具和特效留出空间。幅度较大的动作先预留画幅，而不是逐帧缩放主体。
- 不强制 10 秒、16:9、固定分辨率或固定帧率。按实际生成能力和目标播放器决定；模型不支持用户时长时，说明可生成长度与可行剪辑/分段方案，不截断关键动作，不靠随意变速或复制静帧冒充满足时长。
- 生成参数与导出参数分开记录。仅当编码器或接入方有要求时统一导出；不同动作不因共用播放器就必须一样长。

## 4. 编写完整动作提示词

每个动作输出独立可复制的全文：角色身份、参考图使用方式、行为、分镜、空间约束、结束状态及针对性负面约束。参考图片用实际可访问文件或附件传递，不把本地路径文字当成已上传的参考图。

先按准备、主要表演、跟随动作、收束划分节奏，再映射到实际秒数；阶段可省略或重叠，不把所有动作都套成相同的时间分段。时间轴覆盖整段，不留下未定义间隙；循环可以直接从动作相位开始，不强制预备动作。

```text
基于所附角色参考图制作 {总时长} 的 {播放语义} 动作。
保持角色的 {完整身份特征} 与 {画风、材质、视角} 一致。
本次行为：{具体动作、情绪、力度、参与部位和道具关系}。
起始状态：{姿态、朝向、位置和道具}。
时间分镜：{按本次节奏展开的具体时间区间与表演}。
结束状态：{明确的姿态和下一段衔接要求}。
空间与镜头：{本次允许的位移、镜头、锚点和安全区}。
背景与输出：{背景分离方案及生成服务实际支持的规格}。
避免：{身份漂移、非预期肢体增减、裁切、道具瞬移等相关问题}。
```

只禁止本次不想要的东西：变形动作不能禁止变形，跳跃不能要求双脚全程接地，入睡不能强制片尾睁眼站立。已有非对称形象禁止简单镜像时，左右动作分别制作，不偷用镜像替代。

### 多动作与增量任务

1. 先列出用户需要的全部动作及衔接关系，不漏项，也不添加固定“必做动作”。
2. 有新造型或新制作路线时，选最能验证风险的一段小样：可能是展翼、变形或透明特效，不一定是待机。
3. 已有验证过的角色和管线时直接处理新增动作，不重复生成母图或重做已有小样。
4. 每段独立保存提示词、生成参数和原始输出；失败只重做相关动作。
5. 完整动作库可以有多种时长和播放方式；生成后逐项标记状态，不用部分成功宣称整套完成。

## 5. 生成与媒体处理

### 按实际服务能力生成

检查服务支持的参考图、首尾帧、时长、画幅、种子、透明背景等能力；仅传真实支持的参数。用户指定的服务不可被静默替换；额外付费、上传私有素材或使用新服务前遵守实际授权范围。

参考图或关键姿势是身份控制手段，不是整段动画的替代品。只有用户需要静态姿势集时才以姿势图交付；用户需要连续动作时必须检查中间帧。

### 透明与导出分支

- 已有真实 alpha：保留透明通道处理，不重复抠像。
- 纯色背景：根据角色与道具选择色键并校准容差；不能假设绿幕适用于绿色皮毛、发光或半透明物体。
- 复杂背景、半透明角色、细碎毛发或颜色冲突：使用分割/蒙版或可可靠导出 alpha 的制作工具。检查透明身体和特效是否被当成背景删除。
- 保留背景的普通视频：不做无谓抠像；只有需要透明交付时才检查 alpha。
- PNG 序列与 spritesheet：保持统一舞台、帧序、透明度及帧时长信息。spritesheet 按目标布局和元数据导出，不默认三列两行；像素素材保持采样网格与调色板，不用平滑插值把像素边缘糊掉。
- WebM：按目标选择 VP9-alpha；重解码已有 VP9-alpha 时，在输入 `-i` 前指定 `-c:v libvpx-vp9`，避免透明通道被忽略。
- HEVC-with-Alpha：仅在目标播放器确有需要且编码链可用时采用；普通 HEVC、修改扩展名或仅设置 `hvc1` 不会产生透明视频。用支持该 alpha 层的播放器或原生解码路径验收。

先读取真实元数据，不根据文件名猜分辨率和时长：

```sh
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,width,height,pix_fmt,avg_frame_rate:format=duration \
  -of json "$INPUT"
```

#### 可选：透明中间视频导出 VP9-alpha

仅适用于已验证带 alpha 的中间视频，例如透明 MOV；不负责抠像。先按目标确定 `FPS`，`INPUT` 是真实文件，`OUTPUT` 是尚不存在的 `.webm` 路径。命令保留输入画布，不强制时长或宽高；编码器不接受某种尺寸时，以透明补边等方式适配，不无声拉伸。无音轨是桌宠示例选择，需要声音时另行保留并验证。

```sh
ffmpeg -nostdin -n -i "$INPUT" -map 0:v:0 \
  -vf "fps=${FPS},format=yuva420p" \
  -c:v libvpx-vp9 -crf 30 -b:v 0 -auto-alt-ref 0 -an "$OUTPUT"
```

输入已经是 VP9-alpha WebM 时，应在上述命令的 `-i` 前添加 `-c:v libvpx-vp9`。变更帧率后按输出时间基准检查时长和首尾，不能只看退出码。Windows 使用当前 shell 的环境变量语法；无 ffmpeg 时明确缺少工具，不伪造转码成功。

### 几何对齐

用基准姿态或明确指定的参考帧确定角色尺度与锚点，并将同一变换应用于整段。不要逐帧按包围框居中、缩放或锁定脚底，否则会抹掉跳跃、摆动、伸缩与位移。

姿态过渡的首尾本来不同，不能把两端高度取平均当作站立身高。道具、尾巴、光效和背景噪点不能代替身体基准。检查整段内容范围，防止中间的展翼、跳跃或特效被裁切；动作与既有素材衔接时，复用同一角色的既有舞台和锚点。

## 6. 验收每个动作

|检查项|通过条件|
|---|---|
|身份一致|形态、服饰、配色、标记不意外漂移；允许的变形符合动作卡|
|动作意图|真实完成用户要求的动作、情绪和节奏，不以静帧循环或无关动作代替|
|首尾与衔接|按循环、一次性、过渡或持续状态分别验收，不统一要求回站立|
|空间完整|极限姿态和道具完整，锚点一致，没有意外漂移、穿模或裁切|
|时间与规格|实际时长、帧率、分辨率、帧序和音轨满足目标要求|
|背景与透明|符合输出要求；透明素材无明显残底、误抠、边缘污染或透明度丢失|
|增量兼容|已有素材未被覆盖，新动作边界可接续已有动作|

视频须完整播放，并抽查首尾、动作极值和关键交互帧；循环至少观察两轮。半透明边缘在浅色、深色和棋盘背景上检查。像素帧或 spritesheet 要按真实帧时序播放，不能只看整张图排列正确。

#### VP9-alpha 的最低像素检查

以下仅验证抽样像素中存在不同透明度，不验证动作或边缘质量。`INPUT` 指向待验收的 VP9 WebM；`ALPHA` 指向新的临时 raw 文件。必须先成功解码再读结果，不能沿用旧检查输出。

```sh
ffmpeg -nostdin -n -v error -c:v libvpx-vp9 -i "$INPUT" \
  -an -vf "fps=1,alphaextract" -pix_fmt gray -f rawvideo "$ALPHA" &&
python3 - "$ALPHA" <<'PY'
import sys
from pathlib import Path
alpha = Path(sys.argv[1]).read_bytes()
if not alpha:
    raise SystemExit('FAIL: no alpha samples decoded')
lo, hi = min(alpha), max(alpha)
if lo == hi:
    raise SystemExit('FAIL: no alpha variation; inspect output against the action contract')
print('alpha samples:', lo, hi)
PY
```

幽灵或光效可能全身半透明，不能要求一定出现 alpha=255。消失动作允许指定区间全透明；短暂出现的动作或不足一秒的片段需提高抽样率或逐帧检查，不能用低频抽样结果否定其正确性。`alpha_mode`、文件扩展名或 `pix_fmt` 单独都不是透明效果证据。

## 7. 按目标接入，而不是让动作套固定播放器

只在用户要求运行接入时执行；纯提示词或素材交付不需要安装应用。

1. 阅读目标项目的真实素材契约、导入器、动作绑定及启动方式，沿用其文件组织；不凭旧经验臆造配置字段。
2. 把角色动作映射到运行时需要的入口。点击可以是惊喜、后退或吐槽；待机可以是漂浮、打盹或梳毛；动作名与交互事件不是同一层概念。
3. 只启用已经有素材并经过验收的入口，配置引用与实际文件一一对应。运行时必须字段与用户动作意图冲突时，解释所需适配，不伪造动作支持。
4. 核对默认朝向、镜像规则、锚点、移动驱动、进入/退出时机及循环边界。程序移动与视频内移动不能无意叠加，翻向不能执行两次。
5. 读取配置成品，确认没有校验失败后的默认回落；实际加载素材并触发新增动作、检查过渡和交互。无图形环境时记录哪些视觉验证仍缺失。

在 kodama 仓库接入时，先读取当前 `assets/catalog/`、对应素材说明和 `scripts/assets/` 中实际使用的导入流程；不能把通用视频配置当成现有像素/姿势素材契约，也不为存放本技能修改运行时代码。

## 8. 交付规则

- **提示词任务**：角色身份摘要、动作卡、每个动作完整提示词、对应参考图需求及生成设置。完成提示词交付，不声称媒体已生成。
- **媒体任务**：真实源素材、要求的导出文件、关键生成/处理参数及逐动作验收结果。缺少服务或素材时列出精确缺口，不把提示词当成已完成媒体。
- **动作库增补**：列出新增文件和必要的配置变更，说明与既有动作的衔接；原角色、母图及未请求动作保持不变。
- **接入任务**：补充实际部署位置、启动/重载方法及真实交互证据。编码成功、配置可解析不等于已经播放通过。
- 任务记录沿用现有目录和格式；没有约定时按角色/动作组织参考图、提示词、原始输出和发布素材即可，不建立假装通用的播放器配置 schema。
- 保留有价值的源素材；清理自己生成的临时解码文件、检查脚本和重复预览，不删除用户文件。
